# Implementation status

The product requirements are: a simultaneous multi-device workspace and high-fidelity device frames (both P0), plus responsive tooling, security and packaging. **Verified** means exercised in a running app or a specific test; source presence alone is not acceptance evidence.

| Requirement | Status | Evidence / remaining boundary |
|---|---|---|
| Three initial independent views; six-view capacity | Implemented; runtime verified | Four concurrent local pages observed; add/remove exercised through six views, max-cap rejection, and removal back to four. Six-page load stress is not a performance guarantee. |
| Real interactive content in each device | Implemented; runtime verified | Four pages exposed independent counters and viewport state in the local fixture. |
| Device profiles, CSS viewport, DPR, UA, touch | Implemented; runtime verified | Desktop, iPhone, iPad, and Android fixture pages reported their expected metrics; Chromium emulation only. |
| Rotate device control | Implemented; unit-tested rule | Phones and tablets get a header icon button that toggles portrait/landscape; desktop and laptop profiles have no button and the main process forces their native orientation, including settings loaded from disk. |
| Touch gestures on phones/tablets | Implemented; packaged runtime verified | Real mouse drags on the iPhone and iPad previews produced touch start/move/end with `pointerType: touch` and scrolled the page ~1000 px; the desktop preview received only mouse events. Touch support (`maxTouchPoints` 5, coarse pointer) survived five consecutive navigations after emulation updates were serialized per view. |
| Blisk-style equal-height device panes | Implemented; packaged visual check | In horizontal layout the three panes measured the same height with dividers between them and the device centered; other layouts keep card styling. |
| URL synchronization and legacy-settings migration | Implemented; runtime and migration-test verified | A bare `localhost:3001` address submission synchronized all three active views; in-page fragment navigation propagated to all views. Versionless settings migrate to one shared starting URL and synchronized navigation. |
| Document-scroll synchronization | Implemented; runtime verified | After page navigation, scroll observer bindings remained installed. Scrolling one page to ratio 0.68 moved two other viewport sizes to 0.67982 and 0.67979 (source 0.67995). Physical wheel input and nested scroll containers remain outside verified coverage. |
| Horizontal/grid/vertical layouts; reorder | Horizontal default and fit geometry runtime verified; alternatives source reviewed | Device cards appeared side by side; Fit all placed all three cards inside the canvas. Grid/vertical visual behavior and drag reorder remain unverified. |
| Workspace and panel scale independent of CSS viewport | Implemented; packaged runtime verified | Previews are emulated as non-mobile viewports sized to the native view with DPR/zoom compensation; page metrics stay at the profile values (desktop 1440×900/DPR 1, iPad 768×(1024−74 chrome)/DPR 2, iPhone 390×(844−142 chrome)/DPR 3) and no preview paints outside its frame. |
| Fit workspace, fit active width, actual-size controls | Fit-all runtime and visual verification | Fit all set 27% and all three horizontal device cards fit in the canvas. Fit-width and actual-size were not exercised in the final smoke. |
| Supplied logo | Packaged runtime verified | The packaged app loaded the supplied PNG in its header; the startup surface references the same asset. The generated `.icns` was present in the packaged `.app`, and the macOS DMG built successfully. |
| Device catalog and vector frames | Implemented; unit tests, a sweep of every profile in the running app, and visual checks | About 100 profiles (iPhone, iPad, Galaxy, Pixel, iMac, MacBook, monitors) each with its own frame: model-specific notch, Dynamic Island, punch hole or home button, bezel and finish. The screen opening equals the viewport exactly by construction; tests cover that for every profile, landscape rotation, and cutouts staying inside the status bar. Status bars and Safari/Chrome toolbars are drawn inside the screen; landscape turns the artwork counter-clockwise (camera on the left). Not pixel-compared with real hardware. |
| Per-device user agent and client hints | Implemented; runtime verified | A local header-echo server saw the iPhone, iPad, and Mac Chrome user agents on the first request after launch (previously the default Electron user agent). |
| Previews partly scrolled out of the workspace | Implemented; packaged runtime verified | The native view hides and a last-frame snapshot is drawn in its screen, clipped by the canvas; at 330 px horizontal scroll the desktop frame stayed filled. |
| Add/remove device; preserve unrelated views | Implemented; runtime verified | Added views through six, confirmed seventh was rejected, removed back to four, and retained the other views. |
| Custom dimensions and orientation | Implemented; runtime verified | Custom iPhone width changed the live CSS viewport from 390 to 400; rotation changed it to 844×390. Dimension limits are 240–2400 px. |
| URL navigation and back/forward/reload | Address-bar navigation and fragment sync runtime verified | Submitting `localhost:3001/?framepilot=address` from the workspace address field loaded that URL in all three views. External-site interaction remains a manual acceptance step. |
| Website isolation and navigation restrictions | Implemented; source reviewed | Website contents are sandboxed, have no FramePilot bridge or Node access, and HTTP(S)-only navigation; popups, downloads, and permissions are denied. Adversarial runtime rejection paths were not exercised in this run. |
| Per-view DevTools | Implemented; UI action unverified | Detached Chromium DevTools action exists; opening it through the UI remains manual verification. |
| Actual PNG capture | Implemented; output unverified | Main process uses `capturePage()` and a user-selected folder; dialog and output files remain manual end-to-end verification. |
| Workspace persistence across restart | Implemented; runtime verified | Device profiles, per-device orientation, settings, and synchronized `#checkpoint` survived restart with the same test user-data directory. |
| Error/console reporting | Implemented; source reviewed | Navigation failures and console warnings/errors update workspace state; error display remains unexercised. |
| Auto-refresh, network throttling, named workspaces, screenshot annotation/cloud sharing | Not implemented | These are P1 items and are not claimed as delivered. |

## Completion boundary

P0 acceptance is not complete solely because the app compiles. Foreground manual checks remain for visual frame/aperture alignment, native page input over the frame opening, physical scrolling, drag reorder and fit behavior, screenshot output, DevTools UI, external-site navigation, adversarial navigation/popups/downloads, and packaged icon appearance. No external website behavior is asserted from local fixture tests.
